---
  v1.5+ Feasibility Assessment

  Stack constraints: Tauri v2 Rust, Next.js 14, SQLCipher SQLite, offline-only (no network ever), no external SDKs with network access.

  ---
  ✅ HIGH feasibility

  System-wide theme switcher — LOW priority, Small effort
  - Redesign-A already ships CSS variables + theming infrastructure
  - Just: Zustand store → localStorage → swap CSS class on <html>
  - 1–2 days. No blockers.

  iCalendar import/export (.ics) — MED priority, Medium effort
  - RFC 5545 is a static spec. Rust crate icalendar is mature.
  - Export: serialize SQLite appointments → .ics via Tauri command
  - Import: parse .ics → insert to SQLite
  - No offline constraint conflict. 3–5 days. Low risk.

  Medical code tagging (ICD-10) — LOW priority, Medium effort
  - ICD-10 is a static dataset (~70k codes). Bundle as SQLite table.
  - Match against extracted_text via FTS5 or regex scan at upload time
  - No LLM needed. No network needed.
  - Risk: false-positive rate on fuzzy match. Mitigable with threshold.
  - 1 week.

  ---
  ⚠️ MEDIUM feasibility — architectural cost

  F4.5 Calendar conflict resolution UI — SHOULD priority, Medium effort
  - Apple Calendar integration already done (Phase F4). Event reads work.
  - Conflict detection: query appointments table for overlapping time windows — trivial SQL
  - UI: highlight conflicting rows, offer reschedule/dismiss
  - Blocker: write-back to Apple Calendar — EventKit FFI via Tauri plugin. Doable but macOS-only; Swift bridge or objc FFI needed
  - 1–2 weeks if read-only conflict display. 3–4 weeks if write-back.

  Multi-user vault support — LOW priority, Large effort
  - Each user = separate PBKDF2 key → separate SQLCipher key
  - Needs: user-switching UI, per-user DB file, key derivation on switch, session isolation
  - Current architecture assumes single vault opened at app start. Requires changes to open_database Rust command + frontend auth flow.
  - No network needed (all local). Architecture is clean enough to extend.
  - Estimate: 3–4 weeks. Risk: key management bugs = data loss.

  ---
  🔴 LOW feasibility — large blockers

  LLM-assisted extraction (on-device Mistral 7B via llama.cpp) — POST-MVP, Large effort
  - llama.cpp has Rust bindings (llama-cpp-rs). Offline ✅.
  - Blockers:
    - Model size: Mistral 7B Q4 ≈ 4 GB — can't bundle in app; requires download step
    - RAM: needs 6–8 GB free → unusable on 8 GB machines
    - Cold start: 15–30s on CPU, 5–10s with Metal/CUDA
    - Binary size: llama.cpp adds ~20 MB to app + 4 GB side-car model
    - App signing/notarization: large binaries + side-car complicate macOS Gatekeeper
  - Smarter path: use smaller model (Phi-3-mini 3.8B Q4 ≈ 2.2 GB) or CoreML on macOS (Apple Neural Engine, no llama.cpp needed)
  - Realistic estimate: 6–10 weeks to ship something usable. High risk.

  Outlook Calendar sync (Windows) — MED priority, Large effort
  - Offline-only constraint kills Microsoft Graph API (cloud OAuth)
  - Fallback: Windows COM automation (outlook.exe via Rust FFI / windows-rs crate)
    - Fragile: depends on Outlook being installed, COM version, user permissions
    - No Outlook installed = feature silently unavailable
  - Alternative: read .pst / .ost files directly — no stable open-source Rust parser
  - Tauri is cross-platform but this feature is inherently Windows + Outlook-specific
  - Estimate: 4–6 weeks for COM path. High fragility risk.

  AI appointment notes summarization — LOW priority, Large effort
  - Offline-only = needs on-device LLM → blocked by same issues as Mistral 7B above
  - Without LLM: rule-based extraction already done (Phase 40). Summarization without LLM is just template formatting — low value.
  - Feasibility tied entirely to LLM feature. Don't start until LLM ships.

  ---
  Recommended build order (if proceeding)

  1. Theme switcher — 2 days, zero risk, ships polish
  2. iCalendar .ics — 1 week, clean value, no blockers
  3. ICD-10 tagging — 1 week, offline-safe, adds medical credibility
  4. Calendar conflict UI (read-only display first) — 2 weeks
  5. Multi-user vault — 3–4 weeks, needs careful key management design
  6. LLM (Phi-3-mini, not Mistral 7B) — 6–8 weeks, tackle last
  7. Outlook sync — defer until Windows user base justifies COM fragility risk
